# Heimdall

Heimdall is a command-line helper for managing AWS and Azure sessions and for
creating Kubernetes kubeconfig files. It reduces repeated cloud-login and
context-switching work by selecting AWS profiles or Azure subscriptions,
refreshing authentication when needed, and exporting the selected context into
your current shell.

It supports Linux on `amd64` and `arm64`, with Bash and Zsh shell integration.

## Features

- Filterable interactive selection for AWS profiles, AWS SSO sessions, Azure
  tenants, Azure subscriptions, and Kubernetes clusters.
- Direct AWS profile, AWS SSO session, and Azure subscription selection by
  passing a name or identifier.
- AWS SSO login and generation of AWS profiles for all accessible SSO accounts.
- Parallel EKS discovery across all AWS regions supported by Heimdall and
  kubeconfig generation for the selected cluster.
- AKS discovery in the active Azure subscription and kubeconfig generation
  configured for Azure CLI authentication.
- Shell integration that applies `AWS_PROFILE`, `AZURE_CONFIG_DIR`, and
  `KUBECONFIG` to the invoking shell.
- A built-in `heimdall show` status panel for inspecting the active cloud and
  Kubernetes context without Starship.
- Provider-specific or all-provider context cleanup with `getSunny`.
- Optional Starship prompt integration for displaying cloud and Kubernetes
  context.

## Requirements

Install only the provider tools for the commands you intend to use.

| Dependency | Required | Purpose |
| --- | --- | --- |
| [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) | For AWS commands | AWS SSO login, account discovery, EKS discovery, and kubeconfig generation. |
| [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli) | For Azure commands | Azure login, tenant/subscription selection, AKS discovery, and credential retrieval. |
| [kubelogin](https://azure.github.io/kubelogin/install.html) | For `heimdall az gen kubeConf` | Converts AKS kubeconfigs to use Azure CLI authentication. |
| [kubectl](https://kubernetes.io/docs/tasks/tools/) | for using kubeconfig | Uses the kubeconfig generated by Heimdall and lets `heimdall show` display its active Kubernetes context. |
| --- | --- | --- |
| [Starship](https://starship.rs/) | Optional | Displays the selected AWS, Azure, and Kubernetes context in your prompt. |
| [Mise](https://mise.jdx.dev/) | Optional | Installs and manages selected CLI tools. |
| Go 1.24.1+ | For source installs | Builds and installs Heimdall from source. |

For example, add this to `mise.toml`:

```toml
[tools]
go = "1.24.1"
aws-cli = "latest"
azure = "latest"
kubelogin = "latest"
kubectl = "latest"
starship = "latest"
"go:github.com/BetterCallB4RB4/heimdall" = "latest"
```

Then install the declared tools:

```sh
mise install
```

Install Azure CLI and `kubelogin` using their official platform-specific
instructions linked above.

## Installation

This repository is private. You must have repository access for release or Go
module installation.

<details>
<summary>Release archive</summary>

Download the archive matching your Linux architecture from
[Releases](https://github.com/BetterCallB4RB4/heimdall/releases):

| Machine architecture | Release archive |
| --- | --- |
| `x86_64` | `linux_amd64` |
| `aarch64` | `linux_arm64` |

Check your architecture:

```sh
uname -m
```

Install the downloaded archive for your user:

```sh
mkdir -p ~/.local/bin
tar -xzf heimdall_<version>_linux_<architecture>.tar.gz
install -m 0755 heimdall ~/.local/bin/heimdall
rm heimdall
```

Ensure `~/.local/bin` is on `PATH`:

```sh
export PATH="$HOME/.local/bin:$PATH"
```

Add that line to `~/.bashrc` or `~/.zshrc` if it is not already set. Releases
include `checksums.txt` for download verification.

</details>

<details>
<summary>Go install</summary>

Install the latest version from the private module:

```sh
go install github.com/BetterCallB4RB4/heimdall@latest
```

Go installs the executable into `$(go env GOPATH)/bin`. Ensure that directory
is on `PATH`.

</details>

## Shell Integration

Shell integration is required when a selected profile, subscription, or
kubeconfig must remain active after Heimdall exits. A program cannot change its
parent shell environment, so this function runs the binary, sources its emitted
`export` and `unset` commands, then removes the temporary script.

Add the following to `~/.bashrc` or `~/.zshrc`, then start a new shell:

```sh
heimdall() {
    local tmp_script
    tmp_script="$(mktemp /tmp/heimdall_script.XXXXXX)"

    HEIMDALL_SCRIPT="$tmp_script" command heimdall "$@"

    if [[ -s "$tmp_script" ]]; then
        source "$tmp_script"
    fi
    rm -f "$tmp_script"
}
```

The `command heimdall` expression bypasses the function and invokes the actual
binary found on `PATH`. In Zsh, use `whence -p heimdall` to show that binary.

You can run the binary without this function, but shell context will not be
applied automatically. Heimdall writes the pending commands to
`~/generated_script.sh` in that case.

## Quick Start

### AWS

Define an AWS SSO session in `~/.aws/config`:

```ini
[sso-session default-sso-login]
sso_start_url = https://d-xxxxxxxxxx.awsapps.com/start
sso_region = us-east-1
sso_registration_scopes = sso:account:access
```

Generate one profile for each account available through that SSO session:

```sh
heimdall aws gen ssoProfile default-sso-login
```

Select a generated profile, then create a kubeconfig for an EKS cluster:

```sh
heimdall aws select my-account-sso
heimdall aws gen kubeConf
heimdall show
```

### Azure

Log in, select a tenant and subscription, then create a kubeconfig for an AKS
cluster:

```sh
heimdall az login
heimdall az gen kubeConf
heimdall show
```

## Command Reference

Run `heimdall --help` or `heimdall <command> --help` for Cobra-generated help.
The CLI has no custom flags; `--help` and `--version` are available globally.

### AWS Commands

| Command | Description |
| --- | --- |
| `heimdall aws` | Shows AWS command help. |
| `heimdall aws select [profile]` | Selects an AWS profile. Omit `profile` for interactive selection; providing it selects that profile directly. It refreshes an expired SSO session when possible and exports `AWS_PROFILE`. |
| `heimdall aws login [sso-session]` | Authenticates an AWS SSO session. Omit the session name for interactive selection. |
| `heimdall aws gen` | Shows AWS generation command help. |
| `heimdall aws gen ssoProfile [sso-session]` | Authenticates an SSO session, lists accessible accounts, and creates or updates `<account-name>-sso` profiles in `~/.aws/config`. Omit the session name for interactive selection. |
| `heimdall aws gen kubeConf` | Scans supported AWS regions concurrently for EKS clusters, selects a cluster interactively, writes `~/.kube/clusters/aws/<cluster>`, and exports `KUBECONFIG`. Select an AWS profile first. |
| `heimdall aws getSunny` | Unsets `AWS_PROFILE` and `KUBECONFIG`. |

`aws gen kubeConf` runs `aws eks list-clusters` in parallel across Heimdall's
supported AWS-region list. Each region has a five-second timeout.

### Azure Commands

| Command | Description |
| --- | --- |
| `heimdall az` | Shows Azure command help. |
| `heimdall az login` | Runs Azure browser login, selects a tenant and subscription interactively, and exports a shell-specific `AZURE_CONFIG_DIR`. |
| `heimdall az select [subscription]` | Reuses or refreshes an Azure session and selects a subscription. Omit the argument for interactive selection; provide a subscription name or ID to select it directly. |
| `heimdall az gen` | Shows Azure generation command help. |
| `heimdall az gen kubeConf` | Lists AKS clusters in the active subscription, selects one when necessary, writes `~/.kube/clusters/az/<cluster>`, converts it with `kubelogin`, and exports `KUBECONFIG`. |
| `heimdall az getSunny` | Unsets `AZURE_CONFIG_DIR` and `KUBECONFIG`. |

Azure tenant session data is retained for reuse. `AZURE_CONFIG_DIR` isolates the
active Azure CLI context for the current shell when shell integration is used.

### Show Current Context

```sh
heimdall show
```

Displays the current `AWS_PROFILE`, `AZURE_CONFIG_DIR`, active Azure
subscription, `KUBECONFIG`, and Kubernetes context in a terminal status panel.
It is read-only: it does not start a login, refresh credentials, or modify
configuration. Kubernetes context is shown when `KUBECONFIG` is set and
`kubectl` is available; otherwise it is reported as unavailable.

### Clear Context

```sh
heimdall getSunny
```

This unsets `AWS_PROFILE`, `AZURE_CONFIG_DIR`, and `KUBECONFIG`. It does not
delete AWS SSO cache files or saved Azure tenant sessions.

### Shell Completion

Generate a completion script for a supported shell, then follow the shell's
completion-installation instructions:

```sh
heimdall completion bash
heimdall completion zsh
```

## Optional Starship Prompt

Add this to `~/.config/starship.toml` to show the context selected by Heimdall:

```toml
format = """
$directory\
$git_branch\
$git_status\
$aws\
$azure\
$kubernetes\
$line_break\
$character"""

[aws]
format = ' [$symbol ($profile)(\[$duration\])]($style) '

[azure]
disabled = false
format = '[$symbol ($subscription)]($style) '

[kubernetes]
disabled = false
format = '[$symbol $context]($style) '
```
